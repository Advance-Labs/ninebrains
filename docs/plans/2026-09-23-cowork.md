# Cowork: shared text editing in one remote worktree

Status: implementation in progress. The Unix-socket server, typed desktop Wire bridge,
Monaco/Yjs binding, manual join control, shared Save routing, and reconnect action are in this
checkout. The service is not packaged for release or validated with two Unix users on a Linux
host. The first release targets two
Ninebrains desktop users with
separate Unix accounts on one SSH host, both opening the same Git worktree. Text edits in the
Monaco editor converge live. Cursor presence, terminals, agents, tasks, and Brain state are
outside this first release.

## Current boundaries

- The workspace server accepts multiple Wire sessions, but runs per Unix user with a private
  socket (`apps/workspace-server/docs/daemon.md`). Different SSH accounts do not share it.
- Project and task records live in each desktop's SQLite database. A shared remote path does
  not make task tabs appear in another desktop.
- `OpenFileStore` owns a local buffer per file, writes to the files runtime with an etag
  precondition, and treats disk changes during a dirty buffer as conflicts. That policy cannot
  merge simultaneous typing.
- Ninebrains has not published a remote workspace-server artifact (`docs/FORK.md`, open item 4).
  SSH projects cannot provision in a released app until that prerequisite is addressed.

## User flow

1. Both users configure the same SSH host using their own account and open the same absolute
   repository and worktree path as a project/task workspace in Ninebrains.
2. The editor identifies a shared text document by canonical remote host identity, canonical
   worktree path, and relative file path. Local database IDs are never used as room IDs.
3. Each participant opens a text file and enters the server socket path and token in the Cowork
   toolbar. Typing appears in the other editor without Save.
   Save persists the converged document once, with disk version checks. Closing the tab leaves
   the document without closing the project.
4. If the network drops, edits remain in the local buffer and synchronize on reconnect. A file
   changed by an agent or another program on disk is reconciled explicitly; it must not silently
   replace unsaved collaborative text.

## Host architecture

The per-user workspace servers remain private. Add a narrow, repository-scoped collaboration
service on the SSH host with access to the shared worktree. It exposes only document join,
update, snapshot, and save operations, never arbitrary shell, agent, terminal, or secret APIs.
Clients reach its Unix socket through their existing SSH connections. The host administrator
must grant both Unix users access to the worktree and the socket through a shared group or ACL.
The service checks paths against the configured worktree root after canonicalization and rejects
symlink escapes. The socket is inaccessible to users outside the allowed group. Each desktop
authenticates as a participant using a per-session capability delivered out of band by the
session owner. The current server reads that capability from an owner-only file and keeps it in
memory for constant-time comparison. The desktop currently holds the token only in the open
session; credential storage and invitation UI remain.

Each open document has an authoritative Yjs document. The service loads disk text on first join,
applies binary CRDT updates from participants, broadcasts updates with sequence numbers, and
persists state before acknowledging. The desktop binds the Yjs text to its Monaco model and
keeps existing `OpenFileStore` leases for disk and Git views. Collaborative buffers bypass the
ordinary single-user save path; Save requests the shared service to write the converged text.
The service checks the last observed disk version and reports an external-change conflict if
another process wrote the file. A conflict UI must preserve both versions for review.

Connection loss and process restart exchange a full Yjs state update during manual reconnect.
The service persists each document's CRDT state and last disk version under its own private state
directory outside the worktree. Document IDs are derived from validated root-relative paths.
Bounded update size, document size, and participant count protect the service from resource
exhaustion; documents leave memory when their last participant disconnects.

## Delivery order

1. Ship Ninebrains workspace-server artifacts and verify SSH project setup in a release-like
   environment. This is a prerequisite, not a collaboration API change.
2. Add the narrow collaboration service, host setup command, authenticated join, document
   persistence, and two-client contract tests. The socket service, CLI, and tests are implemented;
   packaged delivery remains. Keep its protocol separate from the full
   workspace-server Wire contract.
3. Add a desktop SSH connection to that service and an opt-in file toolbar action to join
   a session. Implemented with a manual socket/token entry; one-click session creation and
   invitation remain.
4. Bind the shared document to Monaco at the buffer facet. Preserve single-user editing as the
   default when no session is joined. Route Save through the service for joined documents.
   Implemented; dedicated shared conflict resolution UI remains.
5. Exercise simultaneous inserts/deletes, reconnect and restart, external disk writes, permission
   failures, and teardown with two Unix users on a Linux test host.

## Acceptance criteria

- Two separate SSH users type in the same file at once; both editors converge to identical text
  without lost edits or manual reload.
- Save writes that text exactly once to the shared worktree. External disk changes cannot be
  silently overwritten.
- Disconnect and reconnect preserve unsaved typing and converge after recovery.
- A user without access to the configured group/ACL or session capability cannot join, read,
  edit, or save a document.
- Leaving a session restores the existing per-user save/conflict behavior.
- The feature works in a packaged Ninebrains desktop build and on a supported Linux SSH host.

## Dependency review

Yjs and its Monaco binding provide concurrent text merging and a Monaco adapter. The checkout
adds `yjs@13.6.32`, `y-monaco@0.1.6`, and `y-protocols@1.0.7`. `y-monaco` imports
`y-protocols/awareness` without declaring it as a runtime dependency, so the desktop declares it
directly. These packages and their transitive dependencies are MIT licensed. The pnpm lockfile is
updated. Dependency and security review remains part of the implementation PR.
